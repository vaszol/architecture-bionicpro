# Повышение оперативности и стабильности работы CRM

## Архитектура CDC

### Новые компоненты:
- Debezium - CDC для PostgreSQL (pgoutput)
- Kafka - брокер сообщений

### Поток данных:
1. Изменения в CRM DB → logical decoding
2. Debezium → Kafka (топики по таблицам)
3. ClickHouse KafkaEngine → потребление
4. MaterializedView → витрина для отчётов
5. API → новая витрина (без нагрузки на OLTP)

### Преимущества:
- Разделение OLTP и OLAP нагрузок
- Real-time синхронизация данных
- Отказоустойчивость через Kafka
- Масштабируемость

Преимущества решения

- Разделение нагрузок - CDC через Debezium, OLTP и OLAP изолированы
- Real-time синхронизация - Изменения попадают в ClickHouse через Kafka
- Отказоустойчивость - Kafka реплицирует сообщения
- Масштабируемость - Kafka Connect можно кластеризовать
- Снижение нагрузки на CRM - Выгрузки идут из реплики, не из OLTP
