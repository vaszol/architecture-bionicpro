# Снижение нагрузки на базу данных

## Архитектура снижения нагрузки

### Новые компоненты:
- MinIO - S3-совместимое объектное хранилище
- Nginx CDN - reverse proxy с кэшированием

### Поток запроса отчёта:
1. Пользователь → API (запрос отчёта)
2. API → BionicPRO-Report
3. BionicPRO-Report → MinIO (проверка наличия)
4. Если отчёт есть → возвращает CDN URL
5. Если нет → генерирует, сохраняет в MinIO, возвращает CDN URL
6. Фронтенд → Nginx CDN (скачивание)
7. Nginx → MinIO (прокси с кэшированием)

### Структура хранения в S3:
```
bucket: reports/
├── user_{user_id}/
│ ├── prosthetic_{id}/
│ │ ├── 2026-01-01_report.pdf
│ │ ├── 2026-01-02_report.pdf
│ │ ├── latest.pdf
│ │ └── metadata.json
│ └── prosthetic_2/
│   └── ...
└── _cache/
  └── invalidation_tokens.json
```

### Кэширование в Nginx:
- Кэш на 24 часа для отчётов
- Инвалидация при обновлении данных
- Cache-Control заголовки

### Обновление кэша:
- При успешном ETL → инвалидация кэша через API
- DELETE запрос к Nginx для очистки кэша
- Обновление latest.pdf симлинка

### Преимущества решения
- Снижение нагрузки на ClickHouse - Кэширование отчётов в S3, повторные запросы не попадают в БД
- Быстрая раздача - CDN (Nginx) с кэшированием, статические файлы раздаются быстро
- Масштабируемость - S3-хранилище легко масштабируется, CDN можно кластеризовать
- Обновление данных - Инвалидация кэша при обновлении ETL
- Структура хранения - Иерархическая структура user/prosthetic/date для быстрого доступа
